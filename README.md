# 视频配音工具 · 时间轴零漂移

绿色软件，目录 `D:\DubTool\`，双击 **`启动.bat`**（或桌面上的 `视频配音工具.bat`）即可打开图形界面。
不依赖 WorkBuddy、不依赖任何智能体；装好依赖后，选「本地离线语音 + 本地识别」时可完全断网运行。

---

## 节奏策略 v3：句子级波形定长 + 弹性停顿（当前版本）

**它解决了「时快时慢 / 音画轻微错位」。** 旧版把一句话切成十几个窗口，逐段拧 TTS 语速
（实测同一句内 `-13.8% ~ +37.3%` 横跳）把波形硬塞进每个窗口，听感就是一顿一冲。
现在改成：

1. **每句一次整段合成**（`core/sentence.py`），句内保持 TTS 自然语速，**绝不变速**。
2. 句子起点锚定原声窗口起点（＝画面切换点），消除音画错位。
3. 发声时长由合成波形的真实长度决定；只有整句长过「到下一句起点」的空间时，
   才对**整句统一微调一次**（上限 `sentence_max_adjust`，默认 15%），句内依旧同速。
4. 多出来的时间变成自然句间停顿（实测 0.8~1.8s），字幕终点跟着波形走。

新参数：**整句微调上限**（界面第 4 步，0.15＝整句最多 ±15%）。想让句间更紧凑可适度调大，
让整句稍微快点填满窗口；默认 0.15 时本片 10 句微调全为 0%，无需加速。

## 它是怎么工作的（回答「模型直接听原音频吗」）

**不是。** 配音模型从头到尾没听过原音频，只拿到文字。完整链路：

```
视频 ──ffmpeg──> 16k 单声道音轨
                    │
        ┌───────────┴────────────┐
        │                        │
   ① 波形/静音分析          ② 语音识别（文字）
   切出每个发声窗口           本地 SenseVoice / 手动 / SRT
   [(0.000,0.991), …]        → 6 句台词
        │                        │
        └───────────┬────────────┘
                    │  把句子文字按窗口时长分配到 16 个片段
                    ▼
   ③ 语速均衡（core/pace.py）
      按全片统一字速重排文字切点，算出每段 voice_end
      —— 可以借用后续静音，也可以在窗口尾部留白
                    ▼
   ④ TTS 逐片段合成（只输入文字）
                    ▼
   ⑤ 在 TTS 参数域精调每段语速（rate），让自然时长贴近 voice_end；
      逐段频谱/响度匹配到全片参考谱，波形不做相位拉伸
                    ▼
   ⑥ 裁剪/补零到「精确采样点数」压回 voice_end → 拼成 39.520s 整轨
      → 与原画面封装成新视频
```

所以「一秒不差」靠的是**波形时间轴 + 采样点级对齐**，与用什么 TTS 无关；
换音色、换引擎、甚至改台词，时间轴都不变。

### 为什么旧版会「有的特别快、有的特别慢」

这是两个结构性缺陷叠加，不是模型推理失误：

1. **文字切点和窗口时长没有对应关系。** 窗口是波形静音切出来的（时长由原片说话
   节奏决定），整句台词却被 `assign_text` 按标点切成 units；units 数量跟窗口数
   对不上时，就按窗口时长比例硬切字数。于是短窗口可能塞进十几个字、长窗口只放
   六七个字。实测字数密度 3.51 ~ 6.60 字/秒，**相差 1.88 倍**。
2. **每段波形被强制铺满整个窗口。** `fit_exact` 要求输出长度严格等于窗口采样点数，
   字少时长 → 语音被拖成慢腔，字多时短 → 语音被压快甚至裁剪吞字。实测
   `need = 自然时长/目标时长` 落在 0.76 ~ 1.29，正好对应听感上的忽快忽慢。

`core/pace.py` 的修复：全片统一目标字速（本片 4.56 字/秒）→ 按字数反推每段
该占多久 → 文字切点吸附标点并避开词内部 → 允许借静音/尾部留白，`voice_end`
取代窗口终点成为波形铺放目标。`fit_exact` 也加了语速护栏：宁可留白也不把语音
拉成慢腔或压成连珠炮。

用 1.mp4 实测（真实波形测发声时长，非算法自报）：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 逐段感知语速范围 | 3.57 ~ 6.73 字/秒 | 4.59 ~ 6.25 字/秒 |
| 极差 / 均值 | 64% | 33% |
| 标准差 | 0.83 | 0.50 |
| 整轨时长 | 39.520s | 39.520s |
| 漂移 / 异常窗口 | 0.0ms / 2 | 0.0ms / 0 |

对比图：`输出/语速均衡对比.png`。不想用这个功能，把界面「语速均衡」取消勾选即可，
行为退回旧版。

### 为什么旧版会「有时清亮、有时像蒙了一层」

同一个音色、同一段视频里逐段音质不一致，是后处理链引入的，不是 TTS 抽风。
用 1.mp4 实测（同一解码口径、逐段取发声波形）：

1. **相位声码器只作用在部分片段上。** 旧版 `fit_exact` 在 `need = 自然时长/目标时长`
   偏离 1 时调用 `librosa.effects.time_stretch`，`rate≈1` 的段直接跳过。受控实验把
   同一段波形分别按 1.00 / 1.05 / 0.90 变速，谱平坦度从 `0.0031` 涨到
   `0.0056~0.0069` —— 有的段被相位抹糊、有的段保持原生，于是「有时…有时…」。
2. **逐段 tanh 软限幅 + 9kHz 低通。** 波形先被峰值归一到 0.92 再过
   `np.tanh(y*1.10)`，非线性失真把全片谱平坦度从原始 TTS 的 `0.0023~0.0043`
   抬到成品的 `0.0105~0.0174`（3~5 倍），这就是「蒙了一层」的听感来源。
3. **按峰值归一而不是按响度归一。** 擦音多的段落峰值高、平均能量低，整体被压小声，
   实测逐段 RMS 离散 **81%**，听感上就成了「闷」。
4. **TTS 自身的高频波动是固有差异**，不是 bug：不同字的擦音/元音比例不同，
   原始合成结果高频比就有 0.16~0.74 的波动。受控实验把服务端 `rate` 从 -35%
   拉到 +50%，音色指标只变 7~9%，可排除「语速参数改变音色」这个猜想。

`core/align.py` 的修复：把时长调整**前移到 TTS 参数域**（反解
`native(pct) ≈ K/(1+pct/100)`，2 轮精调后自然/目标收敛到 0.97~1.00），
波形一律不做相位拉伸，只裁剪/补静音；去掉 tanh，低通抬到 11.5kHz；
用全片参考谱的中位数做逐段频谱匹配（1/3 倍频程平滑、±4dB 限幅，
不改声线只统一通透度）；改用 RMS 匹配 + 整轨一次线性峰值保护。

| 指标（16 段，同一音色云夏实测） | 修复前 | 修复后 |
|---|---|---|
| 逐段高频比离散 | 153.4% | **44.0%** |
| 谱质心离散 | 65.3% | **23.0%** |
| 谱平坦度离散 | 50.4% | **29.8%** |
| 逐段响度离散 | 81.0% | **1.1%** |
| 全片 6–9kHz 能量占比 | 10.89% | **12.51%** |
| 时长 / 漂移 / 异常窗口 | 39.520s / 0.0ms / 0 | 39.520s / 0.0ms / 0 |

残留的 44% 里有一部分是不同汉字擦音/元音比例的固有差异，强行压平反而会发假；
想再拉齐一点把「匹配强度」调到 1.0 即可。换「云希」音色时同一套参数实测
高频比离散 153.4% → 34.6%、3–6kHz 能量 14.24% → 19.28%。

对比图：`输出/音色一致对比.png`，明细：`work/音质对比.json`。
想退回旧听感，界面勾选「允许波形变速」并取消「音色一致」。

## 有没有「抽卡」（确定性审计）

**默认链路没有抽卡，离线备胎有。** 同一输入重复执行、逐样本对比的结果
（`work/确定性审计.json`、`work/repro/复现结果.json`、`work/缓存验证.json`）：

| 环节 | 重复次数 | 结果 |
|---|---|---|
| edge-tts 云端同参数合成 | 5 | **逐样本完全一致**（md5 全为 `bbb59556…`，262656 样本，corr=1.0） |
| 本地 VITS 同 sid 同文本 | 5 | **每次都不同**：长度 30097~34533，波形 corr ≈ 0，最大差 0.28~0.38 |
| SenseVoice 同音频转写 | 3 | 文字完全一致 |
| ffmpeg AAC 同 wav 编码 | 2 | 容器字节完全一致 |
| 完整链路连跑两遍 | 2 | 48k 音轨 md5 同为 `08996b36…`，rate 表一致，漂移 0.0ms |

所以：**只要用默认的 edge-tts + SenseVoice，同一个视频、同一份时间轴、同一套参数，
跑一百次都是同一条音轨**。服务端是确定性推理（无随机采样），波形切分、频谱匹配、
响度匹配、对齐、封装全是确定性运算，代码里没有任何 `random`。

**真正的抽卡在 `local:` 开头的离线音色。** VITS 是生成式声学模型，随机时长预测器 +
先验噪声采样，实测同一句话 8 次长度 `29768 ~ 35590`（标准差 2393 采样点、
极差/均值 17.7%）。这个波动还会被放大：pipeline 用 `native × (1+pct/100)` 反解
每段语速，`native` 每次不同 → `rate` 表不同 → 成品不同，连频谱匹配的参考谱中位数
也跟着变。想多抽几张挑一张，`离线抽卡次数` 填 5 会取时长最接近中位数的一张，
实测跨轮标准差 2393 → 1593（只降 33%，**不保证跨次一致**）。

**根治办法是锁，不是抽。** 界面「锁定合成结果」默认开启：按
（引擎 / 音色 / sid / rate / speed / pitch / volume / 文本）做 SHA-256 key，
第一次生成后把 float32 波形写入 `work/tts_cache/`，之后命中直接复用。
实测 float32 往返逐样本无损；两个独立的 VITS 引擎实例读同一 key 得到相同 md5；
edge-tts 第二遍 `缓存命中 1 / 新生成 0`，连网络都不请求。附带好处：断网也能
原样复现旧成品、微软服务端日后模型升级不会悄悄改掉你的配音、重跑更快。

改台词、换音色、调语速都会自动 miss（key 变了），不会拿旧声音凑数；
想彻底重抽就点「清空缓存」。自动落盘的 `*_校验报告.json` 里记了每段
`rate_pct`，配合时间轴 JSON 可以完整复盘一次成品。

## 参数（界面里都能改）

| 参数 | 默认 | 含义 |
|---|---|---|
| 句子间隔 | 0.60s | 静音 ≥ 此值判定为句子分界 |
| 最短静音 | 0.20s | 短于此的静音并入发声段，不切窗口 |
| 静音阈值 | -38dB | 同时叠加自适应阈值（95 分位能量 × 0.04），适配不同响度素材 |
| 语速 | -4% | 在线语音基础语速；整句定长时会对整句统一微调（句内不变速） |
| 音调 | -2Hz | 在线语音音高，越低越沉稳 |
| 合成并发 | 4 | 在线语音并发请求数 |
| 语速均衡 | 开 | 重排文字切点与句内停顿；关掉则完全以时间轴 JSON 为准 |
| 整句微调上限 | 0.15 | 句子级定长：整句最多统一加速 15%，句内绝不变速（消除时快时慢） |
| 可借静音 | 0.90s | 单段最多向后借用多少秒静音；越大越能放缓拥挤段，但会吃掉原片留白 |
| 音色一致 | 开 | 逐段频谱/响度匹配到全片参考谱，消除忽清忽糊 |
| 匹配强度 | 0.85 | 0~1；1 为完全拉齐，增益限幅 ±4dB，不会变成电话音 |
| 允许波形变速 | 关 | 打开会启用相位声码器（旧行为，会让部分片段发蒙），仅用于 A/B 对照 |
| 语速精调轮数 | 2 | 在 TTS 参数域把自然时长调到目标，`config.json` 的 `rate_iterations` |
| 整轨峰值 | 0.95 | `config.json` 的 `output_peak`；实测 AAC 192k 无过冲 |
| 锁定合成结果 | 开 | TTS 波形磁盘缓存，成品逐样本可复现、断网可复跑、重跑免请求 |
| 离线抽卡次数 | 1 | `vits_samples`；本地 VITS 每次采样不同，>1 时抽 N 张取时长最稳的一张 |

## 只改一句台词，不重新识别

1. 第一次跑完，在输出目录找到 `*_时间轴.json`；
2. 用记事本打开，改某个片段的 `text`；
3. 界面「复用时间轴」选这个文件 → 「开始配音」。

波形时间轴不动，只重合成语音，漂移依旧是 0。

## 常见问题

- **提示缺模块** → 双击 `一键安装依赖.bat`。
- **提示本地识别模型缺失** → `models/sensevoice/` 里应有 `model.int8.onnx`(229MB) 与 `tokens.txt`；
  缺失时把界面「来源」改成 `manual`，手动粘贴台词即可，不影响对齐。
- **识别不准** → 用 `manual`（每行一句）或 `srt` 导入，识别结果本来就会回填到文本框供修改。
- **没网** → 音色选「本地离线语音 · 男/女声」，来源选 `sensevoice` 或 `manual`，全程离线。
- **切分不对** → 调「静音阈值」「句子间隔」「最短静音」，看日志里打印的窗口数。
- **ffmpeg 位置** → `config.json` 的 `ffmpeg` 字段（默认走 PATH；装了带路径的填这里）。
